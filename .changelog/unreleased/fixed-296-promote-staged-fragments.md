- **`promote` stages the fragments it folds (bob#296).** It renames fragments into `.changelog/promote-staging`, folds the section from the moved bytes once they hash to the index blob, and, after the changelog write succeeds, removes staged paths whose dev and ino still match. A fragment whose moved bytes differ from the preflight index blob is refused. Preflight failures need not create `.changelog/promote-staging`. After staging, move/fold/write failures attempt rollback and report paths that could not be restored; cleanup failures report paths that could not be removed. Exceptions from `afterStage` and `afterWrite` bypass these diagnostics, and checking original paths can fail after staging is removed. The next promote refuses if staging still exists. Entries found at the original paths are reported on a successful promote.
