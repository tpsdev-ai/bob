- **The test suite no longer leaks temp directories under TMPDIR, and the leak check fails when the suite it runs fails (bob#221).** The test files that leaked temporary directories now remove them: positions-195's `loadedPosition` helper (every `bob-pos-dir-*`), `openrouter-provider-183.test.ts` (its per-describe `bob-or*-agents-*`/`-keys-*` roots) and `cli.test.ts` (its scratch HOMEs) track each directory they create and remove it in a file-scope `afterAll`; `session.test.ts` and `turn-admission.test.ts` register their scratch directory for removal BEFORE the setup that can throw, and the work-capability harness removes its scratch directory when its setup throws, so a failed setup in those three cannot leak it. `test/leak-check.test.ts` runs the WHOLE suite in a child process with a fresh TMPDIR and asserts the child EXITED 0, that the file count Bun reports matches the test files under `test/`, and that no top-level entry other than one named `jiti` is left behind (that one entry is excluded by name, so a leak inside it would not be detected). It is opt-in (`BOB_LEAK_CHECK=1`) and runs in its own CI job, so the unit suite stays fast. (`test/leak-check.test.ts`, `test/capabilities/work/run.test.ts`)
