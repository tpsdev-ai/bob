- **The web fetch core: an owned connection with vetted DNS answers, streaming 5 MB caps, a 15-second deadline and pinned extraction (bob#245).** The core is slice R1b of #152 and an internal module (`src/capabilities/web/fetch.ts`, `address.ts`, `url-admission.ts`, `extract.ts`): it registers no tool, and `web_fetch` (slice R1c) is what will call `fetchDocument`. One owned undici `Agent` is built per fetch and destroyed with it. Its connector's `lookup` resolves the name, vets EVERY answer against the address policy and hands those same answers to the socket, so the address that is checked is the address that is connected to and no second resolution can race it; a canonical literal is vetted before dispatch, in every notation WHATWG URL produces. The global dispatcher is never used, no proxy dispatcher is built, and the proxy environment is not read.

  The address policy is versioned and transcribed from the IANA IPv4 and IPv6 special-purpose registries: any address outside global unicast is refused, so are loopback, private-use, shared address space, link-local, benchmarking, documentation, multicast, reserved and broadcast, unique-local and site-local on v6, every transition or translation prefix (NAT64, 6to4, Teredo, the deprecated IPv4-compatible block) and the IPv4-mapped block, the host's own interface addresses, and anything unparsable. One refused answer refuses the whole request. A URL with userinfo, a zone identifier, a scheme other than http or https, or a port other than 443 or 80 is refused before dispatch.

  HTTPS is the default and plain HTTP needs `allow_http`. Redirects are followed by hand, at most five, each target re-admitted and each hop re-vetted, and an https URL is never followed to http; a redirect status with no Location is the final response. The request is GET only, with a fixed `bob/<version>` User-Agent and Accept: no cookies, no Authorization, no referer, and no caller-supplied header.

  One 15-second deadline covers every hop and the body read. The encoded body and the decoded body are each capped at 5 MB, enforced while streaming and before extraction. The allowed content types are HTML, plain text, Markdown, JSON, XML and the RSS/Atom types; anything else is refused naming the type. Scripts, styles, the head and hidden elements are dropped, and a link is kept inline as `text (resolved url)`. The text limit is the operator's `fetch_max_chars` (at most the schema's 100,000) or a lower value the caller asked for; a cut is reported.

  `htmlparser2` 12.0.0 is added as an exact dependency and `undici` (already pinned by the lockfile, 8.10.2) becomes a direct one: the installed tree grew by 767,484 bytes (294,289,386 to 295,056,870) — the extractor and the five packages it pulls in (`entities`, `domhandler`, `domelementtype`, `domutils` and `dom-serializer`). `fetch-core-node.test.ts` drives `test/fixtures/web/fetch-harness.mjs` under Node — the runtime where the owned undici Agent exists, since Bun resolves `undici` to its own implementation — against real HTTP and HTTPS peers on loopback with OS-assigned ports: the fixed headers, the vetted address and the once-per-request resolution, a mixed DNS answer, the literal notations, plain HTTP, the port rule, five redirects and the sixth refused, a redirect to a private address, a redirect to another scheme, the https downgrade and the http upgrade, the redirect with no Location, the encoded and decoded caps, an undecodable encoding and body, the refused content type, every allowed type, the text limit, the deadline, the proxy environment, the global dispatcher, and a network failure. `address-policy.test.ts` pins every registry row and every prefix rule, each with its own sample address; `extract.test.ts` and `fetch-core-units.test.ts` cover the extractor, the text limit and the DNS-answer vetting directly.
