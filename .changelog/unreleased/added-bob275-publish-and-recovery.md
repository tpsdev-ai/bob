- **The `work` capability's `publish` tool: a stored candidate becomes a fast-forward remote commit, with durable recovery after an interrupted push (bob#275, S2b).** Building on S2a's `apply_patch`, `publish` resolves the candidate from tool-owned storage, verifies its task, repository and base association, refuses any changed path outside the task's declared scope, and in `apply` mode requires the candidate tree to BE the task's expected tree. It pins a commit object, materializes the candidate in a fresh tool-owned checkout, and runs every task-declared check through the `run` executor, verifying the materialized tree before and after each command, then pushes fast-forward to the authorized ref only with the expected old ref enforced atomically. A durable intent journal outside the candidate repository is written before any external effect, so an interrupted push is reconciled against the authoritative remote ref on retry rather than duplicated or reported as success. `roles/builder-local/role.json` gains `publish`; the tool's `TOOL_EFFECTS` row is `writer`.
