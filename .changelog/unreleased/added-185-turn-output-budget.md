- **Per-turn reasoning / output budget for local providers, from the selected provider row (bob#185 item 2).** A keyless row may now declare `budget: {maxOutputTokens, reasoning}` — a per-turn output cap and thinking level; a budget on any other row refuses, because bob only enforces it on a `bob/none` row (validated at load: `maxOutputTokens` within [256, 131072], `reasoning` one of `off`, `minimal`, `low`, `medium`, `high`; an out-of-bounds, non-integer, incomplete or unknown field refuses by row name). bob hands the cap to pi as `maxTokens`, which the OpenAI-compatible adapter sends in the provider's own field (`max_completion_tokens`, or `max_tokens` where the model's compat selects it), and the level as pi's thinking level, which the adapter sends as `reasoning_effort` (`off` sends no reasoning directive). The built-in keyless rows (`ollama`, `ollama-newton`, `omlx`) declare a 4096-token output cap and the `low` level; cloud rows declare none, so their requests are unchanged. A request the provider stopped at the row's output cap carries `outputCap` in the run log's request-usage record, so a turn that hit the cap is visible instead of silent. Refs #185.
