- **The Piper install fails closed on a bad swap, and its release check verifies the installed tree.** RUNBOOK step 3 refuses to swap when a previous `lib.new` or `lib.old` is still present, reports a distinct state when `$PIPER_DIR/lib` cannot be inspected, renames directories with `os.rename(2)` so a swap cannot nest one inside the other, and attempts to restore the `lib` it moved aside, reporting a failed restore explicitly. It runs the entry install only after a successful pip install and swap. The release check parses every `<name>-<version>.dist-info` under `$PIPER_DIR/lib`, requires its METADATA `Name` and `Version` to match the directory name and `piper-requirements.txt`, requires the pinned set and no other distribution, and compares each hashed `RECORD` entry that resolves inside `lib` with its file, except a `.pyc` under `__pycache__` that also has an accepted hashless row. A hashless `RECORD` line is accepted only for the distribution's own `RECORD` and for a `.pyc` under `__pycache__`, whose bytes can differ from the wheel's copy; a file `RECORD` does not list is not enumerated. A `RECORD` line may end in CRLF, the terminator pip's CSV writer emits; a carriage return anywhere else in a line is refused. The sidecar refuses to start when `--work-dir` is not an absolute path.
