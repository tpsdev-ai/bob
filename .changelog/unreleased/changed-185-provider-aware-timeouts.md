- **Provider-aware request timeouts and retry policy, from the selected provider row (bob#185 item 1).** A keyless row may now declare `request: {idleTimeoutMs, totalTimeoutMs, maxRetries}` — the request timeout and retry policy for that row; a policy on any other row refuses, because bob only enforces it on a `bob/none` row (validated at load: `idleTimeoutMs` within [1000, 600000] ms, `totalTimeoutMs` 0 or within [900000, 86400000] ms, `maxRetries` within [0, 5]; an out-of-bounds, non-integer, incomplete or unknown field refuses by row name). The built-in keyless rows (`ollama`, `ollama-newton`, `omlx`) declare a 120 s idle/stream timeout, a 30 min total cap and no blind retry; cloud rows declare none, so their timeout and retry behaviour is unchanged. A keyless request no longer carries one cloud-sized total timeout: an idle timer resets on every streamed chunk (queued, prefill and inter-chunk gaps counted) and a timed-out generation fails with a NAMED error — the provider, the limit and the remedy — and is not retried. Refs #185.
