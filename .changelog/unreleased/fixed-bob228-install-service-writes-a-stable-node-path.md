- **`bob install-service` run from an interpreter named `node` writes that interpreter's own path unless a trusted PATH symlink resolves to the same file (bob#228).** It writes, e.g., `/opt/homebrew/bin/node` instead of a versioned Homebrew Cellar path. The choice depends on the basename of the installer's `execPath`, compared case-insensitively, with `.exe` dropped on Windows. When it is not `node` (e.g. bun), the unit's interpreter is the first trusted `node` on PATH (an executable regular file named `node`, not checked to be Node). When it is `node`, the interpreter is the installer's own `execPath`, with one exception: the first trusted PATH `node`, in PATH order, whose final entry is a symlink resolving to the same file is the unit's interpreter instead (for example `/opt/homebrew/bin/node`), preferred even when a direct match — the versioned binary itself — appears earlier on PATH. With no such symlink anywhere on PATH, that `execPath` is used, which can be versioned (observed on Homebrew: `…/Cellar/node/<version>/bin/node`). The written unit follows the written path's later target when it launches — including across a Node major upgrade — and does not re-check it. Both renderers (launchd and the systemd user unit) use the one resolution. A `node` from PATH is used only through a trusted, absolute PATH entry, in both cases (the `execPath` of an installer named `node` is not screened): an entry that is empty or not absolute (`bin`, `.`) is skipped, and a PATH `node` (a file or a symlink) is used only when, following every symlink on the way (a symlinked PATH directory included), every directory on the way is owned by the installing user or by root; the directory holding each symlink, the directory holding each symlink target's final name and the directory holding `node` are writable by no one but their owner, apart from the macOS `admin` group below; and any other directory on the way is group- or other-writable only with the sticky bit or, besides its owner, writable only by that `admin` group. A symlink in an other-writable directory, even a sticky one, or in a directory writable by any group but that `admin` group, is never trusted. On macOS the rule also trusts write by the `admin` group, a policy choice for Homebrew prefixes that are `admin`-writable (observed: `/opt/homebrew/bin` as `drwxrwxr-x <user> admin`). A symlink that lands in a directory writable by any other group is not trusted either: an installer named `node` then takes the next trusted matching symlink on PATH, or its own `execPath` if none remains, and any other installer (e.g. bun) takes the next trusted `node` on PATH or refuses, naming the rejected path. A directory whose owner or mode cannot be read is untrusted. A candidate that fails is skipped, and the resolution continues through PATH as if it were absent; an installer not named `node` that finds no trusted `node` refuses, naming each executable `node` from an absolute PATH entry that the rule rejected.
