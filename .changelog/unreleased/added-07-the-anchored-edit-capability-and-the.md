- **The `anchored-edit` capability and the `builder-local` role: byte-exact, anchor-keyed line edits for builders running on a local model.** A local model that rewrites whole files drifts — it loses the final newline, flips CRLF to LF, drops a BOM, and changes lines it never meant to touch. The new `anchored-edit` capability (`src/capabilities/anchored-edit/`, a blessed catalog entry, its manifest config schema) registers four tools through `pi.registerTool`, beside pi's own `read`/`edit`/`write` (untouched): `read_lines` returns a fingerprint (`F#` = first 16 hex of SHA-256 over the raw bytes) plus an `L<n>#<h>` anchor per line (`h` = FNV-1a 32 over the line's UTF-8 bytes, terminator and a trailing CR stripped; the line number is NOT folded into the hash); `edit_lines` replaces the range between TWO line anchors, inclusive (empty text deletes); `insert_after` inserts after an anchor or `L0`; `write_file` creates exclusively. Edits splice RAW BYTE SPANS, so every byte outside the affected span is unchanged; `read_lines` refuses a file with a NUL byte or invalid UTF-8, and `write_file` refuses NUL content before it creates anything; a line over 2000 characters is shown truncated and cannot be edited; pages are bounded (<=200 lines, <=16 KiB by UTF-8 bytes, cut marker included) and say when cut. The workspace root comes from pi's tool execution context only (never a tool argument or `bob.yaml`); the canonical root is pinned once per session and each path is resolved and checked inside it before every operation, so absolute paths and `..` are refused, a symlink leading outside is refused while an internal one is allowed, temporary files are created exclusively, and a directory replaced by a path that resolves outside the root is refused (the checks compare canonical pathnames, so a directory replaced by another directory at the same pathname is not detected, and a directory swapped by another process between the check and the I/O is a documented, unguarded race, the same class as the cross-process race). Writes are completed until the writer accepts every byte, and an incomplete write is cleaned up and refused. A creation treats any existing entry (including a dangling symlink) as occupied and leaves nothing behind when it refuses, even on an incomplete write. Every refusal names the caller's path and the rule (binary file, out-of-range read, lone CR and overlong line included), a tripped budget answers before the file is read, and a blank line that would become the file's unterminated final line is refused rather than silently dropped. A rewrite tripwire refuses a call that would remove or replace more than half a file (cumulative per file per run, and charged on every later mutation of that file), so a whole-file rewrite cannot fit under it. The new `builder-local` role holds the four anchored tools plus the `work` capability's `run`, `run_status` and `run_cancel` (it holds no `bash`), `grep`, `find`, `ls` and the flair tools, and NO `read`/`edit`/`write`, with `tools.allowResidentShell: true`; the shipped `coder` role is unchanged. Signals (`edit_without_read`, `stale_anchor`, `budget_stop`) ride the structured tool result, and documented gaps live in the capability README. (`test/capabilities/anchored-edit/`)
