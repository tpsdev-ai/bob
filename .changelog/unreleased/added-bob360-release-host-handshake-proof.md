- **The reachy release-host check proves the deployed voice socket completes the `reachy-voice/1` handshake (Refs #360).** Run as bob's own account, it opens the socket the agent's `bob.yaml` names (`reachy.socket`), sends `configure`, and judges the first line by bob's own handshake rules (the shared `checkHealth`: version, profile, wake name, generation, `ok`, and the trained-artifact pair). Every wait is bounded, so it reports a reason instead of hanging, and each failure carries its name: `no-listener` (a refused connect or a missing path, classified by behaviour rather than by errno), `handshake-timeout` (no line within the one limit that covers the `configure` write and its reply), and `handshake-rejected` (a first line bob refuses, naming the mismatched fields). The proof requires bob's reachy capability STOPPED, since its live link consumes the sidecar's one connection; the check's output and RUNBOOK step 8 say so. On the release host it is pinned proof `[P9]`, and its logic is unit-tested against scratch listeners and against the real sidecar.
