- **The reachy release-host check proves the deployed voice socket completes the `reachy-voice/1` handshake (Refs #360).** Run as bob's own account, it opens the socket the agent's `bob.yaml` names (`reachy.socket`), sends `configure` and reads the strict health line back, and passes only when that line reports the configured `sidecarVersion` within a fixed limit. Every wait is bounded, so it reports a reason instead of hanging, and each failure carries its name: `no-listener` (a refused connect or a missing path, classified by behaviour rather than by errno), `busy` (the listener already serves its one connection, so a further connect is refused), `handshake-timeout` (a listener that accepts but does not answer in time), and `version-mismatch`. The proof requires bob's reachy capability STOPPED, since it holds the sidecar's single connection; the check's output and RUNBOOK step 8 say so. On the release host it is pinned proof `[P9]`, and its logic is unit-tested against scratch listeners started in the test.
