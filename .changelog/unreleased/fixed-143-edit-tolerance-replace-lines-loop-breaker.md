- **Edit tolerates whitespace-run mismatches, and a `replace_lines` tool replaces a numbered line range (bob#143).**

  The exact pass runs first: an `oldText` at one exact position is selected by the matcher (pi may still refuse it), and one at more than one exact position (overlapping occurrences included) is refused. Only when it occurs nowhere exactly does the tolerant pass run, with runs of spaces/tabs collapsed and trailing spaces/tabs before LF, CRLF, CR, or the end of the text ignored; CRLF and CR line endings match LF. It accepts only one normalised position (overlapping occurrences included); ambiguous normalised matches are refused before pi's fuzzy pass. A successful normalised retry's result says how many edits needed it. `replace_lines(path, startLine, endLine, newText)` reads the file, validates the range against its content, and writes the range back directly, so the line numbers decide the range; it refuses an inverted or out-of-range range and refuses a write that leaves the run's workspace root. `replace_lines` is named by the `coder`, `writer` and `custom` roles and the `builder` position.

  When the same tool call (identical name and arguments) repeats `run.tool_loop_limit` times in a row (default 4), bob logs a message naming the repeated call, fails the turn and asks the session to stop: a one-shot `bob run` exits non-zero, and the persistent runtime fails the affected turn. A call with a different name or arguments resets the run, so only unbroken repeats fire.
