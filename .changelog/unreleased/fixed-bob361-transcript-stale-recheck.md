- **The reachy transcript path rechecks the link epoch and the effective mute after the memory-attempt audit (bob#361).** A transcript accepted on one connection could write its private memory after the link reconnected, or the mute changed, while the attempt audit was awaited. It now records the connection epoch at acceptance and, after that audit, writes no memory when the epoch advanced or the link is effectively muted, and attempts a refusal linked to the attempt event (the stale rule the action path already applies); the path returns `refused` even if that refusal's audit write fails. A sidecar-reported mute turned on and back off during the audit leaves the link unmuted but advances the epoch, so the epoch recheck refuses it. bob's own mute does not advance the epoch: it is caught when it is still on at the recheck. (`src/capabilities/reachy/capability.ts`, `test/capabilities/reachy/voice-v1.test.ts`)
