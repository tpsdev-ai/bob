- **A streamed `message_update` records which content block its delta came from.** pi streams a message as several blocks — thinking, text, tool-call arguments — and each delta names its own block with `contentIndex`; the projection keeps it beside the inner event's kind. A run that dies before the `message_end` that would describe the message as a whole therefore still leaves deltas that can be attributed and reassembled, instead of text with no place to go.
