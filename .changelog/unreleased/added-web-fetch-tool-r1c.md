- **The `web_fetch` tool: URL provenance, per-operation fetch and text budgets, and web doctor checks (#246; slice R1c of #152).** `web_fetch {url, maxChars?}` fetches a URL and returns its readable text, final URL, HTTP status and content type. A fetched URL must match one recorded from the triggering message or a page already fetched this operation: a recorded reference is parsed with WHATWG URL with its fragment stripped and compared by its serialization (scheme, host, effective port, path and complete query — an empty query stays distinct from none), and the parsed URL is dispatched. For HTML, the extractor records retained, resolvable HTTP(S) anchors resolved against the page; other media are scanned for absolute URLs. Every redirect destination is vetted against provenance before it is followed. An unrecorded URL is refused, suggesting search or asking for the link. Provenance and budgets belong to one admitted operation: the state is seeded on its first prompt and reused across bob's automatic continuations, and no state is exposed once the operation settles. A recorded candidate charges one fetch attempt before the fetch begins (so a failed fetch counts), ten per operation by default, and the extracted document text is charged against a shared allowance of 100,000 characters per operation (the metadata line the tool renders alongside it is not charged). A call outside an admitted operation, or one whose running turn origin differs from the origin the state was seeded for, is refused. `bob doctor` checks the web policy, refuses a known-private address and the NAT64 prefixes, and probes the fetch path without network I/O.
