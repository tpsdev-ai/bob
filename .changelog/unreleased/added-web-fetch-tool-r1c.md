- **The `web_fetch` tool: URL provenance, per-operation fetch and text budgets, and web doctor checks (#246; slice R1c of #152).** `web_fetch {url, maxChars?}` fetches a URL and returns its readable text, final URL, HTTP status and content type. A URL is fetchable only if it appeared in the triggering message or on a page already fetched this operation: a recorded reference is parsed with WHATWG URL with its fragment stripped and compared by its serialization (scheme, host, effective port, path and complete query — an empty query stays distinct from none), and the parsed URL is dispatched. A page's linked URLs are recorded complete: the extractor reports each HTML anchor resolved against the page, and other returned text is scanned for the absolute URLs it holds. Every redirect destination is vetted against provenance before it is followed. An unrecorded URL is refused, suggesting search or asking for the link. Provenance and budgets belong to one admitted operation: the state is seeded on its first prompt and kept, unchanged, across bob's automatic continuations, and a prompt outside any admission seeds nothing. A recorded candidate charges one fetch attempt before the fetch begins (so a failed fetch counts), ten per operation by default, and the extracted document text is charged against a shared allowance of 100,000 characters per operation (the metadata line the tool renders alongside it is not charged). A call outside an admitted operation, or one whose running turn origin differs from the origin the state was seeded for, is refused. `bob doctor` checks the web policy, refuses a known-private address and the NAT64 prefixes, and probes the fetch path without network I/O.
