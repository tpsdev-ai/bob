After a checkpoint, the mid-run check (#214) does not checkpoint again for the same threshold until it re-arms. Only a valid reading (a finite token count above zero) at or below the threshold re-arms it: a tool turn's usage, or a successful compaction's `estimatedTokensAfter` (pi's post-compaction estimate). A tool turn whose usage is not valid (all-zero, which pi's compaction code also treats as carrying no usage data, non-finite or negative) neither re-arms the check nor checkpoints. A successful compaction ends the state a failed or declined compaction leaves (checkpoints off), but with no valid estimate, or an estimate above the threshold, the latch still suppresses checkpoints for that threshold; across repeated over-threshold tool turns after a successful compaction, that suppression is logged once per checkpoint cycle (a cycle ends when the check re-arms or a new checkpoint fires).
