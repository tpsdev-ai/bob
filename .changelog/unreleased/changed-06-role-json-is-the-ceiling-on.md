- **`role.json` is the ceiling on the tool allowlist, and it is read at session creation.** The role's `tools.allow` ships with bob; `bob.yaml` is agent-writable, so `bob.yaml` may only NARROW it: a name the role does not allow is a load error naming the name and the role. The resident opt-in lives in the role schema as `tools.allowResidentShell` — the `coder` role sets it `true`, so a persistent agent of the `coder` role keeps `bash`/`write`/`edit` (builder-local sets it too, and keeps `run` and the anchored-edit writers instead), while no `bob.yaml` can grant itself a shell its role does not allow. A `bob.yaml` whose `agent.role` is missing or unknown is a load error too. (`test/shell/tool-allowlist.test.ts`, `run-tool-allowlist.test.ts`)
