- **A run that only reads now edits or reports BLOCKED (#279).** A local-model builder could spend its whole deadline reading: three measured runs issued 58, 90 and 88 tool calls and ended with no edit, each last message a plan to start editing. `builder-local` now carries an exploration budget of 20 — role.json `exploration_budget`, overridden per agent by bob.yaml `run.exploration_budget` — and a role that names none (every shipped role but `builder-local`) leaves it off. A call is read-only when its `tool-allowlist.ts` row is `read-only` (`read`, `read_lines`, `grep`, `find`, `ls`, `run_status`, `flair_search`, `flair_get`, ...), and a read-only call counts as it starts. A write-class call resets that count only when its execution ENDS WITHOUT AN ERROR (a call that failed or was refused resets nothing), while a command runner (`run`, `bash`, `powershell`) and a name with no `tool-allowlist.ts` row reset nothing however they exit — a command may have only read, so it is not progress (#281). After 20 consecutive read-only calls the runtime injects ONE fixed instruction into the next turn: make the edit now, or report BLOCKED with what is missing. After 20 more read-only calls with still no successful write-class call the run ends with the distinct outcome `exploration_budget_exhausted` (never a silent timeout), recorded in the run log. `bob doctor` gained a last-run line that shows the newest run log's recorded outcome reason and exit code ('no outcome recorded' when the log has none, and the line's status follows the exit code), names the fix when the reason is `exploration_budget_exhausted`, and reads the log's tail as bytes, so a multibyte character split across a read — or the first line of a log shorter than one read — no longer hides the outcome. The budget is enforced on the one-shot run path (`bob run`, `bob launch <name> <prompt>` and a mail turn, which the launcher runs); the persistent runtime's own warm session — cron and Discord turns — does not observe it yet.
