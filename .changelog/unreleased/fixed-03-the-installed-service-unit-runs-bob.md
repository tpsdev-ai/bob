- **The installed service unit invokes bob through an absolute interpreter path named `node` (not checked to be Node), selected at install time (bob#218).** `bob install-service` writes `<node> <bob> run <name>` into both the launchd `ProgramArguments` and the systemd `ExecStart`, where `<node>` is an absolute interpreter path — the installer's own `execPath` when its basename is `node`, otherwise a `node` found on the installer's PATH (since bob#228, a trusted one; see that entry). launchd and systemd both launch a unit with a minimal PATH, and bin/bob's `#!/usr/bin/env node` shebang resolved the interpreter through that PATH — so a node installed outside `/usr/bin` (Homebrew, nvm) was not found and the job exited 127, restarting every throttle interval without ever starting the agent. A bun-launched install no longer writes bun's own path into the unit (bin/bob's shebang and the package's `engines` require Node); it selects a trusted path named `node` on PATH without checking which interpreter that file is, and installation REFUSES, naming the remedy, when no `node` is found on PATH (since bob#228, also when every `node` found is untrusted), and writes nothing. An already-installed unit keeps its old command until it is rewritten, so reinstall it after an upgrade (`bob down <name>`, `bob install-service <name>`, `bob up <name>`). The unit still embeds no secret. (`test/shell/service.test.ts`)
