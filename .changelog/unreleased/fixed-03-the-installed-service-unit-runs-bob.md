- **The installed service unit runs bob under Node, with an absolute interpreter path resolved at install time (bob#218).** `bob install-service` writes `<node> <bob> run <name>` into both the launchd `ProgramArguments` and the systemd `ExecStart`, where `<node>` is an absolute Node executable — the installer's own interpreter when it is Node, otherwise the `node` found on the installer's PATH. launchd and systemd both launch a unit with a minimal PATH, and bin/bob's `#!/usr/bin/env node` shebang resolved the interpreter through that PATH — so a node installed outside `/usr/bin` (Homebrew, nvm) was not found and the job exited 127, restarting every throttle interval without ever starting the agent. A bun-launched install no longer writes a unit that runs bob under bun (bin/bob's shebang and the package's `engines` require Node): installation REFUSES, naming the remedy, when no Node is found, and writes nothing. An already-installed unit keeps its old command until it is rewritten, so reinstall it after an upgrade (`bob down <name>`, `bob install-service <name>`, `bob up <name>`). The unit still embeds no secret. (`test/shell/service.test.ts`)
