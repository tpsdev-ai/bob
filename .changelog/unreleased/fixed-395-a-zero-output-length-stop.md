- **A zero-output `length` stop is left to pi's overflow recovery instead of being re-issued as an empty response (#395).** bob's empty-response wrapper excluded only `error` and `aborted`, so a message with no content blocks and zero output tokens that ended with `stopReason: "length"` was re-issued up to the retry bound and then rewritten as bob's empty-response error, which does not match pi's overflow patterns. The wrapper now passes a response through when pi-ai's own `isContextOverflow` or `isRecoverableLength` classifies it, so pi runs its own recovery instead of bob's empty-response re-issue. For the zero-output `length` stop, pi drops the message, compacts with reason `overflow` and retries once, as it does without bob. A response that ends normally with no content keeps the existing bounded re-issue. (`test/shell/empty-response-381.test.ts`)
