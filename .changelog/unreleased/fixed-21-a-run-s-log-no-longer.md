- **A run's log no longer repeats a growing message on every streamed chunk.** Every `bob run` tees each session event to a per-run JSONL file under `~/agents/<name>/runs/`, and each event is written as a fixed, per-type projection. Of the streamed updates, `message_update` logs the inner event's kind, the content block it belongs to and its delta, `bash_execution_update` its per-chunk delta, `tool_execution_update` the call's identifiers only — not `partialResult`, the cumulative tool output, which is logged once on `tool_execution_end` — and `queue_update` the counts, never the steering/follow-up text. `entry_appended` logs a bounded summary of the entry an extension appended — its type (and a custom entry's `customType`), its id, and the entry's serialized size — and never the entry: `entry` is an extension's own opaque payload, and one that appends a growing session-state snapshot would otherwise put its growth back into the log. An event type bob does not know is logged as its type with none of its payload. The old shape wrote the whole growing message on every streamed token (15 GB of logs on a 40 GB disk, and the disk-full error was swallowed); a record now carries its own named fields only. What that does NOT bound: the records that finalize something — `message_end`, `turn_end`, `agent_end`'s per-run `messages`, a tool's `result` — each carry their payload ONCE and are as large as that payload, and a run writes as many non-delta records as it emits. The log grows with the number of events and with the payload a final record carries; it is not a size cap on either. (`test/shell/run-log-projection.test.ts`, `test/shell/run-log.test.ts`)
